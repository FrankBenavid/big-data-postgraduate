Línea de comandos:
explorar, filtrar y verificar archivos

Una guía práctica para el trabajo en datos · Linux, macOS y una terminal Linux en WSL.

Antes de analizar un archivo es necesario conocer su ubicación, su contenido y el cumplimiento de las condiciones esperadas. La guía presenta comandos pequeños que pueden combinarse para explorar, buscar, resumir y verificar los resultados.

1 · ExplorarUbicar archivos, reconocer su tipo y leer una muestra.pwd · ls · head
2 · ConsultarBuscar coincidencias y trabajar con registros y columnas.grep · wc · awk
3 · VerificarDetectar faltantes, duplicados y diferencias.sort · uniq · diff

Cómo usar esta guía. Los bloques muestran comandos listos para copiar, sin el símbolo del prompt. Los pasos de preparación se ejecutan una vez y se conserva la misma terminal. Las salidas esperadas corresponden a los archivos de práctica incluidos.

Los ejemplos usan Bash o Zsh. En Windows se ejecutan dentro de WSL; no se deben copiar directamente a PowerShell. Algunas opciones adicionales cambian entre macOS y Linux: la ayuda local está disponible mediante man comando.

La idea central: un comando consulta o transforma una entrada y produce una salida. Una salida breve puede revelar un problema; no demuestra por sí sola que todo el archivo sea correcto.

Escenario E1 · Preparación

Preparar el entorno

Se prepara una carpeta de práctica con archivos de contenido conocido.

La terminal es la ventana de interacción; el shell interpreta las instrucciones introducidas. Un comando suele tener la forma comando opciones argumentos. En ls -lh datos/, la opción -l pide detalles y -h presenta tamaños legibles.

cd ~ / cd -Ir a la carpeta personal / volver a la ubicación anterior.

E1 · Paso 1Crear un espacio de trabajo

mkdir practica-cli
cd practica-cli
mkdir datos resultados
pwd

Si practica-cli ya existe, se elige otro nombre para una práctica nueva. Las rutas con espacios se escriben entre comillas: cd "Mis documentos".

E1 · Paso 2Crear los datos del ejercicio

cat > datos/notas.txt <<'EOF'
id;nombre;grupo;nota
1;Ana;A;4.2
2;Luis;B;3.1
3;Marta;A;4.8
4;Juan;B;
3;Marta;A;4.8
5;Sara;C;6.0
EOF

El bloque <<'EOF' entrega varias líneas al comando cat. La línea final EOF debe escribirse sola. En este ejemplo se utiliza punto y coma como separador, punto decimal y una fila de encabezado.

Conservar el original. > crea o sobrescribe el destino. Este bloque se ejecuta únicamente dentro de la carpeta de práctica. El archivo contiene deliberadamente una nota vacía, un identificador repetido y una nota fuera del rango 0 a 5.
Escenario E2 · Inspección

Inspeccionar un archivo

Se reconoce el contenido antes de filtrarlo o modificarlo.

file datos/notas.txt
ls -lh datos/notas.txt
head -n 3 datos/notas.txt
tail -n 2 datos/notas.txt
wc -l datos/notas.txt

La muestra inicial permite reconocer el encabezado y el separador. La muestra final puede revelar un archivo incompleto o registros inesperados. El archivo de práctica tiene 7 líneas terminadas en salto de línea: 1 encabezado y 6 filas de datos.

ComandoCuándo usarlo
cat archivo.txtLeer completo un archivo pequeño.
less archivo.txtExplorar texto largo sin imprimirlo todo en pantalla.
head -n 10 archivo.txtLeer las diez primeras líneas.
tail -n 10 archivo.txtLeer las diez últimas líneas.
tail -f proceso.logObservar nuevas líneas de un registro; salir con Ctrl + C.
nl -ba archivo.txtMostrar números de línea, incluidas las vacías.
sed -n '3,6p' archivo.txtMostrar únicamente las líneas 3 a 6.

Explorar sin perder la ubicación

Dentro de less, se utiliza /Marta para buscar, n para seguir, g para ir al inicio, G para ir al final y q para salir.

find datos -type f -name '*.txt'
du -sh datos
df -h .

find localiza archivos; las comillas conservan el patrón para que lo interprete ese comando. du mide el espacio ocupado y df informa sobre el sistema de archivos donde está la carpeta.

Tipo y extensión son pistas distintas. Un nombre terminado en .csv no garantiza que el contenido sea CSV. file ayuda a reconocer el tipo, pero no valida columnas, reglas del negocio ni todos los registros.
Escenario E3 · Búsqueda

Buscar y contar con grep y wc

Se localizan registros y se cuenta cuántas líneas cumplen una condición.

grep -n 'Marta' datos/notas.txt
grep -c ';A;' datos/notas.txt
grep -v '^id;' datos/notas.txt

La primera consulta encuentra a Marta en las líneas 4 y 6. La segunda devuelve 3 líneas del grupo A. La tercera excluye las líneas que comienzan por id;. Para omitir exactamente la primera línea, se utiliza awk 'NR > 1'.

Opción de grepQué cambia
-nIncluye el número de línea.
-iIgnora diferencias entre mayúsculas y minúsculas.
-vSelecciona líneas que no coinciden.
-cCuenta líneas coincidentes, no apariciones.
-FInterpreta la búsqueda como texto literal.
-EActiva expresiones regulares extendidas.
-r -nBusca recursivamente en una carpeta y muestra líneas.
-C 2Incluye dos líneas de contexto alrededor de cada coincidencia.

Patrones que conviene reconocer

grep '^id;' datos/notas.txt          # Inicio de línea
grep ';$' datos/notas.txt            # Fin de línea
grep -E 'Ana|Luis' datos/notas.txt    # Una alternativa u otra
grep -F '4.8' datos/notas.txt        # Punto literal
grep -n '^[[:space:]]*$' datos/notas.txt

El último comando detecta líneas vacías o compuestas solo por espacios y tabulaciones. No muestra resultados en esta muestra: un campo vacío dentro de una fila no equivale a una línea vacía.

ComandoQué cuenta
wc -l datos/notas.txtSaltos de línea: 7 en la muestra.
wc -w datos/notas.txtPalabras separadas por espacios en blanco; no columnas con punto y coma.
wc -c datos/notas.txtBytes.
wc -m datos/notas.txtCaracteres según la configuración regional.
El último salto importa. wc -l no cuenta una última línea sin salto final. awk 'END {print NR+0}' archivo.txt cuenta también ese registro. Los bytes y los caracteres pueden diferir en texto con tildes.
Escenario E4 · Columnas

Trabajar con AWK

Se seleccionan campos, se aplican condiciones y se calcula un resumen.

AWK procesa registros, normalmente líneas. La forma básica es awk 'condición {acción}' archivo. Sin condición, la acción se aplica a todos los registros. Por defecto separa campos por espacios y tabulaciones; en este caso se declara -F';'.

ElementoSignificado
$0Registro completo.
$1, $2, $NFPrimer campo, segundo campo y último campo.
NR / NFNúmero de registro leído / cantidad de campos del registro.
BEGIN / ENDAcciones antes de leer / después de terminar.
&& / ||Y lógico / O lógico.

Seleccionar y filtrar

# Nombre y nota, sin encabezado
awk -F';' 'NR > 1 {print $2, $4}' datos/notas.txt

# Filas del grupo A
awk -F';' 'NR > 1 && $3 == "A" {print $0}' datos/notas.txt

# Filas con nota presente y dentro del rango esperado
awk -F';' 'NR > 1 && $4 != "" && $4 >= 0 && $4 <= 5 {
  print $2, $4
}' datos/notas.txt

El último filtro devuelve Ana, Luis y Marta dos veces. Una condición de rango no elimina duplicados. En este paso se supone que toda nota no vacía tiene formato numérico; en E5 se comprueba también esa condición.

Calcular con una condición explícita

awk -F';' 'NR > 1 && $4 != "" && $4 >= 0 && $4 <= 5 {
  suma += $4; n++
}
END {
  if (n > 0) printf "Filas: %d | Promedio: %.3f\n", n, suma/n
  else print "Sin notas válidas"
}' datos/notas.txt

Resultado esperado: Filas: 4 | Promedio: 4.225, con punto decimal. El promedio incluye el registro repetido; todavía no es un resultado depurado.

Separar campos no equivale a interpretar CSV. awk -F',' sirve para texto simple separado por comas. Si hay delimitadores entre comillas o saltos dentro de campos, se requiere un lector CSV, por ejemplo el módulo csv de Python. Para TSV simple se utiliza -F'\t'.
Escenario E5 · Calidad

Verificar la estructura y los valores

Se reúne evidencia de los problemas antes de decidir cómo corregirlos.

1. Comprobar columnas y campos obligatorios

awk -F';' 'NF != 4 {print "Columnas incorrectas, línea", NR}' datos/notas.txt
awk -F';' 'NR > 1 && $4 ~ /^[[:space:]]*$/ {
  print "Nota vacía, línea", NR
}' datos/notas.txt

No hay filas con cantidad incorrecta de columnas. Sí hay una nota vacía en la línea 5: la fila conserva sus cuatro campos, aunque el último no tenga contenido.

2. Separar el formato numérico de la regla de rango

awk -F';' 'NR > 1 {
  if ($4 ~ /^[[:space:]]*$/) next
  if ($4 !~ /^[0-9]+([.][0-9]+)?$/)
    print "Formato inválido, línea", NR ":", $4
  else if ($4+0 < 0 || $4+0 > 5)
    print "Fuera de rango, línea", NR ":", $4
}' datos/notas.txt

La regla acepta enteros no negativos y decimales con punto, sin espacios ni signo. La muestra produce Fuera de rango, línea 7: 6.0. Otros formatos, como 4,2, deben tratarse mediante una regla distinta y explícita.

3. Detectar duplicados y frecuencias

# Identificadores presentes más de una vez
awk -F';' 'NR > 1 {print $1}' datos/notas.txt | sort | uniq -d

# Filas completas repetidas, excluyendo el encabezado
awk 'NR > 1' datos/notas.txt | sort | uniq -d

# Cantidad de filas por grupo
awk -F';' 'NR > 1 {print $3}' datos/notas.txt | sort | uniq -c

Los resultados muestran el identificador 3 y la fila 3;Marta;A;4.8 repetidos. Las frecuencias son A: 3, B: 2, C: 1. uniq compara líneas consecutivas; por eso se ordenan primero.

Detectar antes de eliminar. Dos filas con la misma clave pueden contener datos distintos. sort -u elimina líneas idénticas, pero no decide qué registro debe prevalecer cuando una clave tiene versiones diferentes.
Escenario E6 · Flujo de trabajo

Combinar comandos y conservar resultados

Se guarda una salida revisable y se comprueba que el original se conserva.

OperadorFunción
|Envía la salida estándar a la entrada del siguiente comando.
> / >>Sobrescribe el destino / agrega al final.
2>Guarda los mensajes de error.
&&Ejecuta el siguiente comando si el anterior terminó con código 0.
awk -F';' 'NR > 1 {print $3}' datos/notas.txt |
  sort | uniq -c | sort -nr > resultados/frecuencias.txt
cat resultados/frecuencias.txt
cp -i datos/notas.txt resultados/notas_copia.txt
cmp datos/notas.txt resultados/notas_copia.txt

cmp no imprime nada cuando los archivos son idénticos. diff -u original.txt revisado.txt muestra diferencias de texto. En ambos, el código 0 indica igualdad, 1 indica diferencias y los errores usan otros códigos.

Comprobar integridad con SHA-256

# macOS: crear y verificar una lista de huellas
shasum -a 256 datos/notas.txt > resultados/notas.sha256
shasum -a 256 -c resultados/notas.sha256

# Linux con herramientas GNU: alternativa equivalente
sha256sum datos/notas.txt > resultados/notas.sha256
sha256sum -c resultados/notas.sha256

Desde la carpeta de práctica se ejecuta el par correspondiente al sistema operativo. La verificación debe indicar OK. La huella detecta cambios respecto a la referencia; no valida las notas ni la identidad de quien produjo el archivo.

Otros comandos para el trabajo diario

EjemploUso
cut -d';' -f2,4 datos/notas.txtExtraer nombre y nota, incluido el encabezado.
tr '[:lower:]' '[:upper:]' < entrada.txt > salida.txtConvertir letras según la configuración regional.

Entrada y destino deben ser distintos. Debe evitarse sort archivo.txt > archivo.txt: el shell puede vaciar el archivo antes de que sort lo lea. El resultado se guarda con otro nombre y se revisa antes de reemplazar el original.
Desafío · Práctica integradora

Práctica integradora: revisar antes de analizar

Pedro inspecciona los datos y Julia revisa la evidencia de los hallazgos.

La práctica utiliza el archivo de notas. Pedro ejecuta las verificaciones y guarda las salidas; Julia repite los comandos desde la carpeta de práctica y contrasta los resultados. Después intercambian los papeles.

E1–E2 · Ubicar e inspeccionar

Reconocer el archivo

  • ¿Desde qué carpeta deben ejecutarse los ejemplos?
  • ¿Cuál es el separador y cuántas filas de datos hay?
  • ¿Qué evidencia distingue una nota vacía de una línea vacía?
E3–E4 · Consultar y resumir

Explicar los conteos

  • Localizar las apariciones de Marta con sus números de línea.
  • Obtener las frecuencias por grupo y explicar por qué A aparece tres veces.
  • Calcular el promedio de las notas presentes en el rango 0 a 5. ¿Por qué aún contiene un duplicado?
E5–E6 · Verificar y conservar

Proponer una corrección revisable

  • Guardar los identificadores repetidos en resultados/duplicados.txt.
  • Documentar la nota vacía y la nota fuera de rango sin inventar valores de reemplazo.
  • Crear una copia de trabajo y proponer cómo tratar cada hallazgo.
  • Comparar la copia revisada con el original y comprobar la huella del original.
Entrega de la práctica. La entrega incluye los comandos usados, las salidas obtenidas y una breve decisión para cada problema. Una tercera persona debe poder repetir la revisión sin adivinar rutas, separadores ni criterios de validez.

Control para la revisión: 6 filas de datos; Marta en las líneas 4 y 6; nota vacía en la línea 5; valor 6.0 en la línea 7; identificador 3 repetido. Si se elimina solo la fila idéntica duplicada y se excluyen la nota vacía y la nota fuera de rango, quedan 3 notas y su promedio es aproximadamente 4.033. Esa exclusión es una decisión de la práctica, no una regla universal.

Cuando una salida no coincide

  1. Comprobar la ubicación con pwd y el nombre con ls.
  2. Revisar el encabezado, el separador y los finales de línea.
  3. Confirmar si el conteo incluye encabezados, duplicados o campos vacíos.
  4. Ejecutar cada etapa de una tubería por separado para localizar la diferencia.

grep termina con código 0 si encontró coincidencias y con 1 si no encontró ninguna; un error usa un código distinto. Por eso grep patrón archivo && otro_comando solo ejecuta el segundo comando cuando hay coincidencias.

Interpretación y referencias

Consulta de detalles y diferencias entre implementaciones.

La lista reúne 100 comandos distintos por nombre, agrupados por finalidad. Incluye herramientas externas y comandos internos del shell. No representa una clasificación medida de frecuencia de uso.

ARCHIVO, N, PID, los usuarios y los destinos representan valores que deben adaptarse al caso. Las opciones no se combinan automáticamente: cada ejemplo utiliza solo las necesarias. En comandos internos de Bash, help nombre ofrece ayuda local; para herramientas externas se utiliza man nombre.
